# แต้มสะสมลูกค้า

- เลือกลูกค้าใน POS ก่อนชำระ ทุกยอดจ่ายจริงครบ 50 บาทได้ 1 แต้ม ปัดเศษทิ้งรายบิล เริ่มเฉพาะบิลใหม่หลังเปิดฟีเจอร์
- ยอดสินค้าหลังส่วนลดอื่น ก่อนใช้แต้ม ต้องถึง 1,000 บาทจึงใช้แต้มได้ 1 แต้มลด 1 บาท ไม่เกินยอดสินค้าและแต้มที่มี
- ตัวอย่างสินค้า 1,000 บาท ใช้ 100 แต้ม จ่าย 900 บาท ได้เพิ่ม 18 แต้ม
- POS แสดงยอดแต้มและปุ่มใช้แต้ม หน้า **ลูกค้า → ประวัติการซื้อ** แสดงยอดแต้ม วันสมัคร และวันหมดอายุ ใบเสร็จอย่างย่อแสดงแต้มที่ได้/ใช้และยอดหลังบิลนั้น
- วันสมัครคือวันที่เพิ่มรายชื่อลูกค้าลงระบบ (created_at เดิม) ทุกวันครบรอบปีเวลา 00:00 น. ประเทศไทย แต้มรอบเก่าใช้ไม่ได้ทันที ไม่ใช่สิ้นปีปฏิทิน วันสมัคร 29 ก.พ. ใช้ 28 ก.พ. ในปีไม่อธิกสุรทิน
- ยกเลิกบิลจะนำแต้มที่ได้ออกและคืนแต้มที่ใช้ เฉพาะรอบที่ยังไม่หมดอายุ หากแต้มที่ได้ถูกใช้ไปแล้วจึงยกเลิกบิลต้นทาง ระบบพักยอดใช้ได้ที่ 0 และหักชดเชยจากแต้มใหม่ก่อน ยอดค้างนี้สิ้นสุดพร้อมรอบปี
- พักออเดอร์ยังไม่ได้/ไม่ใช้แต้ม เมื่อดึงกลับมาให้เลือกใช้แต้มใหม่

## การเก็บและตรวจสอบ

ใช้ `sales.data.loyalty` ที่แก้ไขเองไม่ได้เป็นประวัติแต้ม และ `contacts.data.loyaltyJoinedAt` เป็นวันสมัครที่เซิร์ฟเวอร์ป้องกันการแก้ทับ ไม่เพิ่มตารางซ้ำหรือสแกนสินค้าทั้งหมด ตัวอ่านกรองลูกค้าและรอบปีผ่านดัชนี ยอดรวมข้ามคลัง แต่ไม่เปิดเผยรายการขายของคลังที่ไม่มีสิทธิ์

แต้มถูกตรวจและบันทึกในธุรกรรมเดียวกับบิล สต๊อก และกะ ล็อกลูกค้าป้องกันใช้แต้มพร้อมกัน ใช้ request id เดิมเมื่อการชำระยังไม่ทราบผล ป้องกันได้แต้มซ้ำ วันหมดอายุบังคับตอนอ่านและตอนใช้ ไม่ต้องรอ cron ลบประวัติ

สำรอง/กู้คืนด้วยระบบ backup เดิมจะเก็บข้อมูล JSON ทั้งสองส่วนไว้ การหมดอายุไม่ลบหลักฐานบิลและ AUDIT LOG

## ทดสอบ

- `node tests/customer-loyalty-browser.test.js` และ `--built` ทดสอบหน้า POS ยอดชำระ ข้อผิดพลาด และคำขอซ้ำ (จำลอง API)
- `tests/customer-loyalty.sql` ใช้ฟังก์ชันฐานข้อมูลจริงกับตารางชั่วคราว ครอบคลุมวันครบรอบ ปีอธิกสุรทิน ยกเลิกบิล และการป้องกันวันสมัคร
- `tests/customer-loyalty-checkout.sql` เรียกขั้นตอนชำระจริงใน transaction ที่ rollback ตรวจการได้รับ/ใช้แต้มและ idempotency ไม่ทิ้งบิลทดสอบไว้
